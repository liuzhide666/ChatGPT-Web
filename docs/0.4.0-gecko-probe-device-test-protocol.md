# ChatGPT Web 0.4.0 Gecko Probe — Device Validation Protocol

## 1. Purpose and gate

This protocol validates the side-by-side Probe package `com.liuchenlin.chatgptweb.geckoprobe` before any same-package 0.4.0 upgrade. Device QA does not begin until the build environment has independently printed `GECKOVIEW_OFFLINE_OK` and the Probe APK has passed host/static checks.

The key scientific question is not whether Android shows a microphone permission indicator. The decisive chain is: Android `RECORD_AUDIO` permission → trusted Gecko media request → Gecko offers `SOURCE_MICROPHONE` → the exact offered microphone object is selected → Gecko reports `RECORDING type=MICROPHONE status=RECORDING` → ChatGPT Voice can actually send and receive audio.

## 2. Privacy boundary

Use a test conversation with no personal material. Do not upload full logcat. Do not upload full UI tree. Do not preserve screenshots unless a visual defect specifically needs evidence, and crop/redact them before sharing. The evidence package must not contain conversation text, account identifiers, cookies, authorization headers, access/refresh tokens, WebRTC SDP, request bodies, email addresses, phone numbers, or file-system paths from user content.

The supplied capture script intentionally saves only `ChatGPTWeb/Permission`, `ChatGPTWeb/Media`, `ChatGPTWeb/Session`, `ChatGPTWeb/Navigation`, and `ChatGPTWeb/Recovery` records plus non-account device/build metadata. It does not call screenshot or UI-dump commands.

## 3. Preflight

1. Confirm `adb devices` shows exactly the intended device/emulator as `device` rather than `offline` or `unauthorized`.
2. Confirm the Probe package is installed; do not uninstall the existing `com.liuchenlin.chatgptweb` 0.3.x app.
3. Resolve the Probe launcher activity before launching it.
4. Record Android SDK level, ABI list, Probe versionName/versionCode, and installed APK path using the evidence helper.
5. Confirm the original 0.3.x and the Gecko Probe coexist. This is the A/B safety property; failure here blocks the experiment.

If automated tapping is needed, follow the Test Android Apps rule: derive coordinates from a transient `uiautomator` tree, not from screenshot guessing. Delete the transient tree after the coordinate is obtained and do not upload full UI tree. If Gecko page controls are not exposed to UIAutomator, perform the page interaction manually instead of guessing coordinates.

## 4. Baseline browser flow

Before microphone testing, verify the Probe can launch, render ChatGPT over HTTPS with the native Gecko UA, sign in through the normal web flow, send a neutral text message, survive ordinary navigation, and upload one deliberately non-sensitive test file through the Android system picker. A first Gecko login may be required because WebView cookies are not migrated.

Failure at this stage is classified separately from media failure. In particular, absence of the ChatGPT Voice UI is `PRODUCT / UA COMPATIBILITY`, not evidence of an Android microphone defect.

## 5. Microphone experiment

1. Clear logcat with the helper immediately before the experiment.
2. Open a neutral ChatGPT conversation and start Voice manually (or by UI-tree-derived coordinates if available).
3. If Android requests microphone permission, grant `RECORD_AUDIO` normally. Do not grant unrelated permissions merely to make the test pass.
4. Speak a neutral phrase such as “microphone test one two three”, wait for a response, then stop Voice.
5. Immediately capture the filtered evidence with the helper.
6. Inspect the evidence in order. Expected positive events are:
   - `ANDROID_REQUEST permission=RECORD_AUDIO` when the OS prompt is needed;
   - `ANDROID_RESULT permission=RECORD_AUDIO granted=true`;
   - `MEDIA_REQUEST origin=https://chatgpt.com` (or another explicitly trusted OpenAI/ChatGPT HTTPS origin);
   - `AUDIO_SOURCE` entries showing offered source classifications;
   - `AUDIO_SELECTED source=MICROPHONE`;
   - `RECORDING type=MICROPHONE status=RECORDING`.

`SOURCE_MICROPHONE` being offered is stronger than Android permission alone. `MICROPHONE + RECORDING` is the minimum proof that the Gecko media stack reached actual recording state. ChatGPT Voice target success additionally requires observable bidirectional conversation audio.

## 6. Interpretation matrix

| Gecko evidence | Voice result | Interpretation |
| --- | --- | --- |
| `SOURCE_MICROPHONE` + `MICROPHONE/RECORDING` | works | WebView/Chromium path becomes a strong root-cause candidate |
| `SOURCE_MICROPHONE` + `MICROPHONE/RECORDING` | fails | inspect product/UA/WebRTC/network/signalling rather than Android permission |
| physical microphone offered but never `RECORDING` | fails | suspect Gecko→Android audio bridge / 卓易通 path |
| no `SOURCE_MICROPHONE` offered | fails | suspect lower-level audio-device exposure in compatibility layer |
| Android `RECORD_AUDIO` cannot be granted | fails | Android/卓易通 runtime permission layer |
| Voice UI absent | not testable | product/Firefox-UA compatibility result; do not spoof Chrome in 0.4.0 |

## 7. Background and recovery

Host tests own the exact `599999 ms` versus `600000 ms` boundary. Device validation uses practical windows: return once well below ten minutes and confirm the current page is preserved without forced reload; return once clearly beyond ten minutes and confirm exactly one reload. System permission dialogs and the file picker are external flows and must not start the ten-minute background timer.

For process-death recovery, put the Probe in the background, terminate the app process through an Android test/debug mechanism, relaunch, and confirm saved Gecko session state is restored when available. Do not deliberately create repeated low-level content-process crashes on a personal device solely to test the crash-loop guard; the deterministic 3-failures/60-seconds rule is covered by host tests, while any naturally occurring `onCrash`/`onKill` should be captured under `ChatGPTWeb/Recovery`.

## 8. Completion language

A successful install or Android permission grant is not “Voice fixed.” Use these status labels precisely:

- `Probe build verified`: real pinned GeckoView/AGP build and APK static checks passed.
- `Gecko microphone chain verified`: evidence contains physical `SOURCE_MICROPHONE` selection and `RECORDING type=MICROPHONE status=RECORDING`.
- `0.4.0 Voice target achieved`: ChatGPT Voice is actually bidirectional on the target 卓易通 device.
- `Formal in-place upgrade compatible`: only after the formal package is signed and its signer SHA-256 exactly matches the frozen certificate baseline.
